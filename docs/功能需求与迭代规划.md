# TinyPendingItem 功能需求与迭代规划

| 版本 | 日期 | 说明 |
|---|---|---|
| v1.0 | 2026-10-16 | 评审通过稿（含账号登录与数据隔离需求） |
| v1.1 | 2026-10-16 | 取消桌面端规划，明确仅做网页版 |

## 1. 产品定位

TinyPendingItem 是一个**轻量级个人待办任务列表**：注册即用、随记随办的最小待办清单。

- **目标用户**：需要快速记录零散待办的用户（含开发者自用）
- **设计原则**：
  - 最小实现优先：每期迭代交付完整可用的闭环，明确不做的功能坚决不做
  - 数据安全：多账号存在时数据按账号严格隔离，仅本人可见
  - 低维护：与兄弟项目（TinyMusic、AnimeViewer 等）同技术栈
- **非目标（整个产品当前阶段不做）**：桌面客户端（Tauri/Electron 等，仅做网页版）、团队协作、复杂项目/子任务管理、日历排期

## 2. 使用场景

1. **随手记**：想到一件事 → 打开页面 → 输入回车 → 关闭窗口，全程不到 10 秒
2. **清单一遍过**：打开列表逐条勾选完成，用完即删
3. **多设备/多浏览器**：换设备登录同一账号，清单照常在（数据权威存服务端，MVP 即具备）
4. **换机迁移**：无需任何导出导入操作（导入导出备份属于迭代三）

## 3. 术语表

| 术语 | 含义 |
|---|---|
| 待办项（PendingItem） | 一条任务，最小数据单元 |
| 待办 / 已完成 | `done` 状态的两态文案 |
| 数据隔离 | 账号 B 登录后看不到账号 A 的任何数据 |

## 4. 账号与安全（MVP 必备）

### 4.1 注册

- 用户名 + 密码注册；用户名全局唯一
- 约束：用户名 3–20 个字符；密码至少 6 位（MVP 级别）
- 密码以 bcrypt 哈希存储，任何环节不可见明文
- **边界**：不支持邮箱/手机注册、无验证码、无找回密码

### 4.2 登录与会话

- 登录成功签发 JWT，有效期 7 天
- 登录后刷新页面、重开浏览器保持登录
- token 失效或接口返回 401 时，自动清除本地会话并回到登录页
- 退出登录 = 清除本地 token

### 4.3 数据隔离（验收级要求）

- 所有待办数据按账号隔离
- 隔离由**服务端强制实现**（token 解出身份 + SQL 强制按 user_id 过滤），不依赖前端行为；技术细节见《技术架构设计.md》第 7 节

## 6. MVP 功能详细描述

### F1 快速添加
- 输入框置于列表顶部，回车即添加
- 添加后输入框清空并保持焦点，支持连续录入
- 空输入/纯空格不产生条目；标题去首尾空格
- 标题上限 50 字符，超限前端提示不提交

### F2 列表展示
- 顶部统计：总数 N、剩余待办 M（如「共 10 条 · 待办 3」）
- 空列表显示占位文案（引导使用）
- 条目显示：标题、创建时间（相对时间可选）

### F3 筛选
- 三个 tab：全部 / 进行中 / 已完成
- 切换为前端过滤，不重新请求

### F4 完成/撤销
- 复选框切换 done 状态，完成时间记录在 doneAt
- 完成项样式：文字置灰 + 划线
- 筛选状态下勾选/撤销，条目即时归入对应视图

### F5 删除
- 条目右侧删除按钮，点击直接删除

### F6 持久化
- 权威数据存服务端 SQLite
- 所有条目操作落库成功后更新前端状态

## 7. 非功能需求

| 维度 | 要求 |
|---|---|
| 性能 | 页面冷启动 <1s；连续添加 10 条无可感知卡顿 |
| 兼容 | 主流 Chromium 浏览器最新版 |
| 安全 | 数据库中无明文密码；未登录访问业务接口一律 401 |
| 可维护性 | `vue-tsc` 无类型错误；`vitest` 覆盖认证/隔离与前端核心逻辑 |

## 8. 验收标准

### 8.1 迭代一 MVP

- **功能**：F1–F8 行为符合第 6 节与第 4 节描述
- **隔离**：注册账号 A、B 并各自录入数据；B 登录后看不到 A 的任何数据；A 重新登录数据完好
- **安全**：数据库文件中无明文密码；未登录调用 `/api/items/*` 返回 401
- **会话**：登录后刷新页面保持登录；token 过期/无效后自动回到登录页
- **质量**：`vue-tsc` 无错误；`vitest` 全部通过

### 8.2 后续迭代

每期迭代范围在开发前评审时随上期交付情况补充细化验收标准，原则不变：每期独立可交付、可部署、可验收。
