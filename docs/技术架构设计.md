# TinyPendingItem 技术架构设计

| 版本 | 日期 | 说明 |
|---|---|---|
| v1.0 | 2026-10-16 | 评审通过稿（含轻后端、账号登录与数据隔离） |
| v1.1 | 2026-10-16 | 取消桌面端（Tauri）规划，仅保留网页版交付 |

## 1. 概述

TinyPendingItem 是轻量级个人待办应用，由两部分组成：

- **前端**：Vite + Vue 3 单页应用，登录/注册 + 待办主界面
- **轻后端**：极小的 Node.js 服务，负责账号认证与待办数据存取，同时托管前端静态产物

核心架构决策：**账号与数据隔离是硬需求 → 权威数据源必须在一处**，因此采用轻后端 + 服务端数据库，而不是纯前端本地多账号（后者密码只能明文/弱哈希存在浏览器，隔离不了会话，也无法跨设备）。

## 2. 技术选型

### 2.1 前端

| 层 | 选型 | 理由 |
|---|---|---|
| 构建 | Vite 6 + TypeScript | 与兄弟项目（TinyMusic、AnimeViewer）一致，工具链复用 |
| 视图 | Vue 3 `<script setup>` | 单页面应用，MVP 无需 vue-router |
| 状态 | Pinia | 兄弟项目同款；stores 承载认证与待办两个模块 |
| UI | Naive UI | 三态筛选 tab、轻提示等开箱即用，从迭代一引入 |
| HTTP | fetch 封装 | 请求量小，自封装 401 统一跳转即可 |

### 2.2 后端

| 层 | 选型 | 理由 |
|---|---|---|
| 框架 | Node.js + Express（tsx 运行 TS） | 最小依赖，规模可控在 5 个文件以内 |
| 数据库 | SQLite（better-sqlite3，单文件 tiny.db） | 零部署、零服务，天然适合轻应用；同步 API 简化代码 |
| 认证 | jsonwebtoken（JWT，7 天有效） | 无状态会话，MVP 不做服务端吊销 |
| 密码 | bcryptjs | 哈希存储，杜绝明文 |

被否决的替代方案：纯前端 localStorage 多账号（弱隔离、单设备，见第 1 节）；云数据库/独立 DB 服务（对单机轻应用过重）。

## 3. 系统结构与数据流

```
浏览器（Vue SPA）
   │  HTTPS/HTTP + Bearer token
   ▼
Express 轻后端（同端口托管 dist/ 静态文件）
   ├─ /api/auth/*   注册 / 登录 / 当前用户
   ├─ /api/items/*  待办 CRUD（全部经 auth 中间件）
   └─ better-sqlite3 → tiny.db（ users 表 + items 表）
```

前端数据流：Pinia store 发起请求 → fetch 封装附带 token → 后端校验并以 userId 过滤 → 返回数据更新 store → UI 渲染。所有条目操作等后端成功响应后再更新本地状态，保证权威数据在服务端。

## 4. 数据模型

```sql
CREATE TABLE users (
  id            INTEGER PRIMARY KEY AUTOINCREMENT,
  username      TEXT NOT NULL UNIQUE,
  password_hash TEXT NOT NULL,
  created_at    INTEGER NOT NULL          -- 毫秒时间戳
);

CREATE TABLE items (
  id         INTEGER PRIMARY KEY AUTOINCREMENT,
  user_id    INTEGER NOT NULL REFERENCES users(id),
  title      TEXT NOT NULL,               -- ≤ 50 字符
  done       INTEGER NOT NULL DEFAULT 0,  -- 0/1
  created_at INTEGER NOT NULL,
  done_at    INTEGER                      -- 完成时间，可空
);
CREATE INDEX idx_items_user ON items(user_id, created_at);
```

前后端统一用 TS 类型表达（前端 `src/types.ts` 与后端 `server/types.ts` 各自声明同构类型）：

```ts
interface User { id: number; username: string }
interface PendingItem { id: number; userId: number; title: string; done: boolean; createdAt: number; doneAt?: number }
```

## 5. 后端设计与 API

### 5.1 目录结构（控制在 5 个文件左右）

```
server/
├── index.ts        # 入口：中间件、静态托管、启动
├── db.ts           # better-sqlite3 初始化 + 建表迁移
├── auth.ts         # 注册/登录路由 + JWT 签发与校验中间件
├── items.ts        # items CRUD 路由
└── types.ts        # 共享类型
```

### 5.2 认证与授权流程

1. `POST /api/auth/register`：校验用户名 3–20 字符、密码 ≥6 位 → bcrypt 哈希 → 写 users → 返回 token（注册即登录）
2. `POST /api/auth/login`：bcrypt 比对 → 签发 JWT（payload `{ uid }`，7 天）
3. `GET /api/auth/me`：验签后返回 `{ id, username }`
4. auth 中间件：读 `Authorization: Bearer <token>` → jwt.verify → `req.userId` 注入；失败一律 401
5. 静态托管与 `/api` 之外的路径回退到 `index.html`（前端路由预留）

### 5.3 API 一览

| 方法 | 路径 | 说明 | 成功返回 |
|---|---|---|---|
| POST | /api/auth/register | 注册并登录 | `{ token, user }` |
| POST | /api/auth/login | 登录 | `{ token, user }` |
| GET | /api/auth/me | 当前用户 | `{ user }` |
| GET | /api/items | 当前用户全部条目（按 created_at 倒序） | `{ items }` |
| POST | /api/items | 新增条目 | `{ item }` |
| PATCH | /api/items/:id | 切换完成/撤销 | `{ item }` |
| DELETE | /api/items/:id | 删除条目 | 204 |

错误约定：401 未登录/token 无效；400 参数不合法；404 条目不存在（含不属于本人时——不区分 403/404 以免泄漏他人资源存在性）。

### 5.4 数据隔离的实现（验收级）

- items 三个接口全部由 auth 中间件先取 `req.userId`
- SQL 一律由**服务端拼接** user_id 条件，前端传入的任何 userId 请求体字段一律忽略：
  - `SELECT … WHERE user_id = ?`
  - `UPDATE items SET done = ? WHERE id = ? AND user_id = ?`
  - `DELETE FROM items WHERE id = ? AND user_id = ?`
- UPDATE/DELETE 影响行数为 0 时返回 404——他人条目对本账号表现为不存在
- 该行为写入验收标准：账号 B 无法读取、修改、删除账号 A 的任何条目

## 6. 前端设计

```
src/
├── main.ts
├── App.vue              # 根组件：按登录态切换 登录页/主界面
├── types.ts
├── api/
│   └── client.ts        # fetch 封装：附 token、统一错误、401 事件分发
├── stores/
│   ├── auth.ts          # token、user、login/register/logout
│   └── items.ts         # 列表、筛选状态、增删改查 action
└── components/
    ├── LoginView.vue    # 登录/注册二合一页面
    ├── TodoApp.vue      # 主界面容器
    ├── AddTodo.vue      # 快速添加输入框（F1）
    ├── TodoList.vue     # 列表 + 三态筛选 tab（F2/F3）
    └── TodoItem.vue     # 单条：勾选/删除（F4/F5）
```

- 会话持久化：token 存 localStorage，应用启动时若有 token 则 `GET /api/auth/me` 验证存活
- 401 处理：client.ts 捕获 401 → 清空 auth store → 回登录页（MVP 无路由，直接条件渲染切换）
- MVP 明确不做 vue-router、路由守卫；需要时迭代二引入

## 7. 安全策略

| 项 | 策略 |
|---|---|
| 密码存储 | bcryptjs 哈希（cost ≥10），任何接口不返回哈希 |
| 会话 | JWT HS256，密钥来自环境变量（`JWT_SECRET`，缺省时启动报错） |
| 输入校验 | 服务端二次校验标题非空、≤50 字符、密码强度 |
| SQL 注入 | better-sqlite3 全部参数化查询 |
| 隔离 | 见 5.4，服务端强制 user_id 过滤 |
| CORS | 同机部署同源访问，开发期由 Vite proxy 解决，生产不开 CORS |
| token 吊销 | MVP 不做（logout 仅前端清 token）；迭代四考虑 |

## 8. 构建与运行

- 开发：`npm run dev:server`（tsx server/index.ts）+ `npm run dev`（vite，/api 代理到后端）
- 测试：`vue-tsc --noEmit`；`vitest`（后端隔离/认证测试 + 前端 stores 测试）
- 生产：`vite build` → `server/index.ts` 同端口托管 `dist/`，单进程单端口即可部署
- `tiny.db` 与 JWT 密钥不入库（.gitignore / 环境变量）

## 10. 后续迭代技术预留

- **迭代二**：编辑/优先级/截止日期 = items 表加列（SQLite `ALTER TABLE` 迁移）；拖拽排序加 `sort_order` 列
- **迭代三**：导入导出 JSON 复用现有 API 全量拉取/批量提交；暗色模式用 Naive UI theme 切换
- **迭代四**：越迁 IndexedDB/PWA 影响数据层接口；refresh token 为 users 表加 token 表
- 存储层到达膨胀阈值（或单库文件 > 数十 MB）时再评估更重的数据库，当前 SQLite 足够

## 11. 技术风险与对策

| 风险 | 对策 |
|---|---|
| better-sqlite3 原生模块在部分环境编译失败 | 锁定 Node LTS；备选 `node:sqlite` 内置模块或 pure-JS sql.js |
| 服务端单点（SQLite 单文件 + 单进程） | 个人轻应用可接受；定期按需备份 tiny.db，迭代三导入导出兜底 |
| JWT 泄漏（localStorage） | MVP 可接受；迭代四 refresh token + 可吊销 |
| 明确不做被临时加需求 | 以本文档 5.4/7 节隔离与安全底线为准，其他按迭代规划走评审 |
